# Remote-signer metering

The pinned go-livepeer signer emits `create_signed_ticket` monitoring events to Kafka after signing. The event includes `auth_id`, state/session identifiers, timestamps, pixels, sequence number, ticket count, and computed fee. The Clearinghouse sets `auth_id` to its workload ID during authenticated authorization, providing a direct attribution key.

The consumer strictly decodes canonical UUIDs and redundant timestamps, ignores unrelated event types, and derives an idempotent usage ID from signer identity plus transport event ID. Attribution also requires the configured signer identity, authorized state ID, and orchestrator address (when present) to agree; mismatches remain visible as unmatched evidence rather than being charged to an account. Deterministically malformed records are committed and skipped so a poison record cannot stall its partition, while transport and persistence failures retry without advancing the offset. Pixel-priced work uses pixels; second/hour pricing uses exact nanosecond duration and ceiling arithmetic.

Kafka production in go-livepeer is asynchronous. Broker failure, process loss, or queue exhaustion can lose a final event. The core therefore does not claim settlement or billing completeness; it reports received evidence and exposes unmatched/divergent costs for operational review. Alternative measurement and reconciliation can be layered as a versioned event source without changing workload authorization.
