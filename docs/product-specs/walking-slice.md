# Production-ready walking slice

A user can sign in by email OTP, discover Livepeer offers, create an immutable
quoted workload with an optional enforced maximum spend and returned-once
workload SDK token, run through the remote signer, and inspect attributed usage,
pending authorization exposure, remaining ceiling, and both quote-derived and
signer-reported cost. Trusted automation may instead use a returned-once,
revocable account API credential for control-plane requests. Google/GitHub may
be enabled independently. An administrator signs in with the configured email,
inspects users/workloads/usage, and controls a global authorization stop.

The default deployment uses four services and durable SQLite/Redpanda/signer volumes. It includes no commercial billing, ledger, organization tenancy, invitation, dynamic adapter loading, OpenMeter, Stripe, Auth0, Turnkey, or go-livepeer patch.

The UX retains the validated Pymthouse-derived information density, navigation model, dark zinc/emerald language, responsive shell, semantic markup, global CSS control, and Shadow Part contract.
